// How to Work: ETL and ELT
/*
    Data Pipeline can be:
        ELT: Data is stable - from x to y directly
            and transformation happen in one place.
        ETL: Data is not stable. we need transformation.
            --> Ex: Source (API) - Staging Area (Here Transformation) - Target

        T (Transformation): we transforme data means we change data into useful format.
            Where that transformation happen: the place that script launched (Staging Area).

    But How to choose right data pipeline:
        - Volumetrie (Quantity of data)
        - Conformite (Security for personnal data (like morrocan data should not be in cloud))
        - Felexiblite (Ability to change transformations)
        - Coût de calcul (Cost of processing data)
        - Vitesse (How quickly data becomes available)

    When to use ELT and ETL:
        - ELT: Get all Data. And Then we gonna look what we need to with this data.
        - ETL: We do not need all data for get insight.
*/

// Data Lake, Lake House, Data Warehouses
/*
    - Data Lake(Cloud Storage): centralized storage that can hold anything (vides, files, images, parquet).
        --> We use this because we do not know why we need this data.

    - Data Warehouse(Big Query[Anayltics exit here]): There is restriction. data is structured (csv file). and data come from deffrent source. we know where we want to go. and data warehouse is result of data modeling. we start by data modeling and then data warehouse.

    - Lakehouse: We merge Datalake and Data Warehouse. Means I am dealing with data as files but storage as Lake (there is parquet file).

    - Delta Lake: Makes a Lakehouse powerful by storing data in Parquet files while allowing us to manage and query data as tables using SQL.

    - LakeHouse Support:
        - Transction ACID
        - Time Travel
        - Enforce Schema: we can not insert something deffrent to table model
        - Upsert (merge): insert and update in same time.
*/

// OLAP and OLTP
/*
    - We need to know our goal: analyzing data or performing transactions.
    - These are two concepts that help us define how we use a database.

    OLTP (transactional):
        Our goal is to store and manage data for daily operations (crud operations).
        - Example: recording a bank transaction.
        - Examples of databases: Oracle, MySQL, PostgreSQL.

    OLAP (analytical):
        Our goal is to analyze data, often including historical data, to understand trends and make decisions.
        - Example: analyzing bank transactions over the last 5 years.
*/
