// ETL and ELT
/*
    Data Pipeline can be:
        ELT: Data is stable from x to y directly.
            and transformation happen in one place.
        ETL: Data is not stable. we need transformation.
            --> Ex: Source (API) - Staging Area - Target

        T (Transformation): we transforme data in place
            that script launch (Staging Are).

    But Why There two parts:
        - Volumetrie
        - Conformite (Security for personnal data (like morrocan data in cloud))
        - Felexiblite
        - Calcul Cost
        - Vitesse

    When to use ELT and ETL:
        - ELT: Get all Data. And Then we gonna look what we need.
        - ETL: We do not need all data for get insight
*/

// Data Lake, Lake House, Data Warehouses

    - Data Warehouse(Big Query[Anayltics exit here]): There is restriction. data is structured (csv file). and data come from deffrent source. we know where we want to go. and data warehouse is result of data modeling. we start by data modeling and then data warehouse.

    - Lakehouse: We merge Datalake and Data Warehouse. Means I am dealing with data as files but storage as Lake (there is parquet file).

    - What LakeHouse Add:
        - Transction ACID
        - Time Travel
        - Enforce Shema: we can not insert something deffrent to table model
        - Upsert (merge): insert and update
